# CROXER 간단 UT 활동 순서와 구현 범위

첫 UT에서는 전체 서비스 대신 **정해진 활동 흐름**을 구현하고, 참가자가 브리핑에서 정한 순서에 따라 역할·활동 화면을 연결한다. 이 문서는 팀의 UT 프로토타입 명세(이미지)를 저장소 문서로 옮긴 것이다. 화면 데이터와 ID는 [UT 데이터 베이스라인](ut-data-baseline.md), 상태 규칙은 [PRD](prd.md) 6.2를 따른다.

## 1. 반드시 지켜야 할 규칙

- 브리핑의 01·02·03 활동만 서로 순서를 바꿀 수 있다. 가능한 배열은 6가지다.
- 04·05 활동은 순서를 바꿀 수 없다. 이동 핸들을 제공하지 않고, 다른 카드를 이 두 자리로 옮길 수도 없다.
- 참가자가 확정한 01·02·03의 순서에 따라 활동 진입 순서와 역할 화면이 함께 바뀐다.
- UT 종료 시 스케줄의 `진행 후` 영역에는 ChatGPT 구독 연장하기와 팀플회의(교양 팀장 녹음)가 남아 있어야 한다.

## 2. 브리핑 초기 목록

| 초기 순번 | 활동 / 역할 | 순서 변경 | UT 처리 |
| --- | --- | --- | --- |
| 01 | 지역 활성화 사례 리서치 검토 / 교양 3조 팀장 | 가능 · 01~03끼리만 | Task 4 화면으로 연결 |
| 02 | 강변 촬영 / 편집자 | 가능 · 01~03끼리만 | Task 6 화면으로 연결 |
| 03 | 한강 러닝 / 러닝 크루장 | 가능 · 01~03끼리만 | Task 8 관련 흐름으로 연결 |
| 04 | ChatGPT 구독 연장하기 / 교양 3조 팀장 | 불가 · 뒤쪽 순서 유지 | 진행하지 않음 · 남은 활동 |
| 05 | 팀플회의 / 교양 팀장 녹음 / 교양 3조 팀장 | 불가 · 뒤쪽 순서 유지 | 진행하지 않음 · 남은 활동 |

## 3. 순서 변경과 화면 연결

- 초기 순서 예시: 리서치 검토 → 강변 촬영 → 한강 러닝 → 구독 연장 → 팀플회의
- 변경 순서 예시: 한강 러닝 → 리서치 검토 → 강변 촬영 → 구독 연장 → 팀플회의
- 변경 후 역할 흐름: 러닝 크루장 → 교양 3조 팀장 → 편집자. 역할에 맞는 화면과 내용도 같은 순서로 연결한다.
- 브리핑 표시 순번과 Task 번호는 다르다. 카드를 옮겨도 Task 4·6·8·9의 식별 번호는 바뀌지 않는다.
- 참가자의 순서를 존중하기 위해 비·문의 같은 돌발 상황은 **해당 활동에 진입했을 때** 발생한다.
- 한 활동의 UT 흐름을 마치면 그 활동을 완료 처리하고, 역할 전환 패널이 다음 순서의 활동을 안내한다. 참가자가 전환이나 유지를 선택한다.

## 4. 실제 구현할 활동과 돌발 태스크

| Task | 활동 / 역할 | 발생 조건 · 연결 | UT에서 수행할 내용 |
| --- | --- | --- | --- |
| Task 4 | 어제 밤 정리한 자료 / 교양 3조 팀장 | 리서치 검토 순서가 되었을 때 | 정리된 자료를 확인하고 검토를 마친다 |
| Task 6 | 강변 촬영 / 편집자 | 강변 촬영 순서가 되었을 때. 비로 인한 돌발 상황 포함 | 촬영 자료 확인 → 비 알림 → 대안 확인·대화. 세부 분기는 준비된 화면으로 연결 |
| Task 8 | 러닝 문의 확인 및 답변 / 러닝 크루장 | 한강 러닝 흐름 진입 시 날씨에 따른 크루원 문의 발생 | 문의 확인 → 대체 코스 확인·선택 → 변경 공지 확인·답변 |
| Task 9 | 러닝 중 백그라운드 작업 요청 / 러닝 진행 중 | Task 8 이후 러닝을 시작한 상태에서 참가자가 채팅을 직접 열 때 | 내일 강변 촬영에 쓸 레퍼런스 정리를 요청한다. 요청 접수와 백그라운드 실행 상태를 표시 |

## 5. Task 9의 연결 규칙

- Task 9는 브리핑의 독립된 카드가 아니다. 러닝 중에 발생하는 추가 요청이다.
- 01·02·03의 배열이 바뀌어도 Task 9는 러닝 흐름에 붙어 실행된다. 전체 순서의 맨 끝에 강제로 붙이지 않는다.
- 예: 러닝을 첫 번째로 옮기면 러닝 문의 응대 → 러닝 중 자료 요청 → 다음 리서치 활동 순으로 이어진다.
- 요청을 보냈다는 사실과 자료 정리가 완료됐다는 사실을 구분한다. 요청 접수만으로 정리 완료 처리하지 않는다.

## 6. UT 종료 시 스케줄 상태

| 스케줄 영역 | 종료 시 표시 상태 |
| --- | --- |
| 진행 후 · 활동 1 | ChatGPT 구독 연장하기 / 교양 3조 팀장 / 미완료 |
| 진행 후 · 활동 2 | 팀플회의(교양 팀장 녹음) / 교양 3조 팀장 / 미완료 |
| 진행 완료 | 01·02·03은 각 UT 흐름을 마치면 완료 처리해 진행 완료 영역에 표시 |
| 진행 중 / 백그라운드 | 현재 활동의 진행 중 상태와 AI의 백그라운드 실행 상태를 구분. 요청 접수만으로 완료 처리하지 않음 |

## 7. 구현 시 상태 관리와 완료 검증

1. 활동에는 고유 ID, 역할, 상태, 순서 변경 가능 여부를 따로 보관한다. 화면 표시 순번을 고유 ID로 사용하지 않는다.
2. 순서 변경 대상 배열은 리서치·촬영·러닝 세 항목만 포함한다. 구독 연장·팀플회의 두 항목은 뒤에 고정해 합친다.
3. 세 항목의 6가지 순서 모두에서 올바른 역할 화면과 활동 내용이 열리는지 확인한다.
4. 구독 연장·팀플회의를 드래그하거나 앞쪽 카드로 밀어도 위치가 바뀌지 않아야 한다.
5. 러닝의 위치와 관계없이 Task 8 → 러닝 중 Task 9가 이어져야 한다.
6. UT 종료 후 스케줄을 열면 `진행 후`에는 구독 연장·팀플회의만 남고, 마친 활동은 `진행 완료`에 표시되어야 한다.

## 8. 구현 범위 메모

- 이 문서는 활동 순서, 역할 화면, 종료 상태를 정의한다. 실제 결제, 실제 회의 녹음, 외부 서비스 연동은 구현하지 않는다. 구독 연장과 팀플회의는 목록에만 보이는 남은 활동이며 별도 화면이 없다.
- 비 알림의 세부 분기, 화면별 문구와 전환 방식은 기존 디자인을 따른다. 이 문서만으로 새로운 일정 교체 규칙이나 시간 값을 만들지 않는다.
- 첫 UT에는 강변 촬영을 다른 날로 미루는 일정 교체를 넣지 않는다(2026-11-14 팀 결정).
