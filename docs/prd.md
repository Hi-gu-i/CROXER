# CROXER 제품 요구사항 정의서

- 작성일: 2026-11-14
- 문서 상태: 논의된 기획 기반 초안
- 목적: 바이브코딩으로 UT용 프로토타입을 구현하기 위한 제품·기능·화면·상태 기준 정의
- 적용 범위: 서비스의 핵심 방향과 첫 UT에 필요한 구현 요구사항

> 이 문서의 요구사항은 구현 완료를 의미하지 않는다. 서비스의 전체 방향과 첫 UT 구현 범위를 구분하며, 논의되지 않은 정책·기술 선택·수치 목표는 확정하지 않는다. 미정 사항은 11장에 모아 두었다. 구체적인 인물, 날짜, 대화 전문과 과제별 진행 순서는 별도의 UT 시나리오 및 데이터 문서에서 관리한다.

## 1. 제품 개요

### 1.1 서비스 정의

CROXER는 여러 역할과 활동을 병행하는 크로스 플레이어의 활동 맥락을 이어주고, 현재 활동과 상황에 맞춰 필요한 정보와 기능을 구성하는 **다이나믹 UI(Dynamic UI)**를 제공하는 Agentic AI 서비스다.

### 1.2 해결할 문제

여러 활동을 병행하는 사용자는 활동을 전환할 때마다 흩어진 자료와 대화를 찾고, 이전 진행 상황을 떠올리며 필요한 도구를 다시 준비해야 한다. 갑작스러운 일정 변화가 발생하면 다른 활동과 마감에 미치는 영향도 직접 확인해야 한다.

CROXER는 활동별 맥락을 유지하고 필요한 정보와 기능을 준비해, 반복적인 확인·준비와 활동 전환에 드는 부담을 줄인다.

### 1.3 대상 사용자

학업, 콘텐츠 제작, 커뮤니티 운영 등 여러 직업과 활동을 병행하는 크로스 플레이어를 대상으로 한다. 새로운 활동을 시작하지 못하는 문제보다, 이미 수행 중인 다양한 활동을 관리하고 전환하는 데 어려움을 겪는 사용자를 중심에 둔다.

### 1.4 제품 목표

| 목표 | 제공할 경험 |
|---|---|
| 활동 전환 부담 감소 | 관련 자료와 이전 진행 상황을 다시 찾지 않고 이어서 활동함 |
| 현재 활동에 집중 | 브리핑에서 맨 위에 둔 활동을 홈에서 먼저 확인함 |
| 상황에 맞는 화면 제공 | 활동 목적에 맞춰 필요한 정보·기능·배치가 달라짐 |
| 맥락을 반영한 AI 지원 | 활동 조건과 일정, 작업 패턴을 고려한 제안을 확인함 |
| 사용자 주도권 유지 | AI의 위임 수준을 설정하고, 제안 수락과 활동 전환을 직접 선택함 |

정량 KPI와 목표 수치는 아직 정하지 않았다. 첫 UT에서는 기능 이해와 사용 과정의 어려움을 중심으로 검증한다.

## 2. 핵심 개념과 용어

| 용어 | 정의 |
|---|---|
| 역할 | 활동을 수행할 때의 사용자 역할. 학생·편집자·러닝 크루장 등 |
| 활동 | 역할에 속해 지속적으로 관리하는 단위. 프로젝트·촬영·러닝 등 |
| 일정 | 활동을 수행하기로 정한 시간과 진행 상태 |
| 할 일 | 활동 안에서 지금 수행해야 할 구체적인 일 |
| 자료 | 활동에 연결된 문서·레퍼런스·메모 등의 정보 |
| 활동 기억 | 특정 활동에 적용되는 사용자의 조건과 선호 |
| 맥락 | 활동을 이어가기 위해 필요한 자료·대화·일정·진행 상황·활동 기억 |
| AI 작업 | AI에게 맡긴 업무. 사용자 일정의 진행 상태와 별도로 관리 |
| 위임 수준 | AI가 업무를 어느 단계까지 진행할지 정하는 설정 |
| 다이나믹 UI | 활동과 상황에 맞춰 정보·기능·화면 구성이 달라지는 인터페이스 |

역할과 활동은 구분한다. 역할 표시 이름이 바뀌더라도 동일한 역할의 식별자는 유지한다. 사용자 화면에서는 활동 안의 구체적인 일을 ‘할 일’로 표현하고, UT의 ‘Task’는 테스트 과제를 뜻한다.

## 3. 제품 범위

### 3.1 첫 UT 구현 범위

| 영역 | 구현 내용 |
|---|---|
| 셋업 | 역할·활동 등록, 활동 상세 확인·수정, 목표 입력, 위임 수준·알림 설정 선택과 저장 |
| 브리핑 | 오늘 활동 확인, 표시 순서 변경과 저장 |
| 홈 | 브리핑에서 맨 위에 둔 활동, 관련 정보·기능의 개요, AI 작업 상태 확인 |
| 활동 화면 | 리서치, 촬영, 러닝 등 목적별 정보와 기능 제공 |
| 활동 전환 | 역할·활동 전환 안내, 유지 또는 전환 선택, 다음 활동 UI 표시 |
| AI 지원 | 상황 알림, 조건 입력과 기억, 대안 확인, 일정 변경 수락 |
| 협업 대응 | 공통 문의 요약, AI 판단과 구분, 코스 선택, 공지 초안 확인·모의 발송 |
| AI 업무 위임 | 다른 활동을 수행하는 동안 업무 요청, 작업 상태와 완료 결과 확인 |
| 스케줄 | 오늘·내일 일정, 사용자 지정 순서, 진행 상태와 변경 결과 확인 |
| 리포트 | 오늘의 활동 결과·패턴 확인, 도움이 된 항목 선택과 피드백 저장 |

### 3.2 전체 기획에 포함되지만 첫 UT에서 제외하는 범위

- 외부 계정을 실제 연동해 활동을 자동으로 발견하는 기능.
- AI가 실시간으로 새로운 화면 구조를 생성하는 기능.
- 위임 수준에 따라 실제 실행 권한과 동작이 달라지는 기능.
- 알림 설정에 따라 실제 알림 전달 시점이 달라지는 기능.
- 별도 승인 대기 목록, 구독 결제, 회의 녹음 시나리오.
- 주간·시즌 리포트의 상세 기능.
- 실제 외부 메시지 전송, 실시간 위치 공유·센서 측정 연동.

첫 UT의 AI 응답·검색 결과·추천·측정값에는 준비된 가상 데이터를 사용한다. 실제 외부 데이터 분석이나 AI의 범용 추론 성능을 검증하는 것으로 해석하지 않는다.

### 3.3 설정 기능의 구현 한계

위임 수준과 알림 방식은 선택·저장 경험까지 구현한다. 후속 동작의 차이는 첫 UT에서 구현하지 않으며, 일정 변경과 공지 발송은 설정과 관계없이 사용자의 명시적 확인을 거친다. 이 제한을 참가자에게 알리는 시점과 방식은 미정이다.

## 4. 정보 구조와 핵심 흐름

### 4.1 정보 구조

| 영역 | 주요 화면·정보 |
|---|---|
| 시작 | 서비스 미리보기, 역할·활동 등록, 활동 상세, 위임 수준, 알림 설정 |
| 홈 | 대표 활동 카드, AI 조언, AI 작업 상태·결과 |
| 활동 | 활동별 자료·기능, AI 채팅, 제안 검토, 활동 기억 |
| 스케줄 | 오늘·내일 일정, 순서와 진행 상태 |
| 리포트 | 오늘 리포트, 주간·시즌 리포트 확장 방향 |
| 설정 | 위임 수준·알림 방식 변경 방향. 상세 구조는 미정 |

### 4.2 핵심 흐름

활동 등록·기본 설정 → 오늘의 브리핑 → 홈에서 활동 확인 → 활동 수행 및 AI 지원 → 다음 활동으로 전환 → 스케줄·리포트 확인

활동 전환 제안에서 ‘유지하기’를 선택하면 현재 역할을 유지한다. 일정 변경 제안을 수락하지 않으면 기존 일정 시각을 유지한다. 위임한 AI 작업이 완료되어도 역할이 자동으로 바뀌지 않는다.

## 5. 기능 요구사항

### F-01. 역할·활동 등록 및 상세 설정

**목적:** 관리할 활동과 활동별 맥락을 설정한다.

- 첫 UT는 등록된 역할·활동이 없는 상태에서 시작한다.
- 사용자가 역할을 등록하고 해당 역할에 활동을 연결한다. 자연스러운 별칭은 같은 역할로 인정한다.
- 등록한 활동에는 준비된 일정과 자료를 동일한 활동 식별자로 연결한다. 촬영·러닝·자료 정리는 역할 등록 후 제공되는 예시 활동이다.
- 활동 목록에서 상세 화면을 열어 활동 정보를 확인·수정한다.
- 상세 화면에는 활동명, 역할, 활동 설명, 연결할 자료, 목표 입력 영역을 제공한다.
- 상세 확인·수정과 목표 입력은 한 화면에서 처리한다. 목표만 입력하기 위해 활동별로 다시 순회하는 단계는 만들지 않는다.
- 목표는 자유로운 문장으로 입력할 수 있게 한다.
- 필수 입력값과 취소 시 변경값 처리 기준은 미정이다.

**확인 기준:** 등록·수정한 활동 정보가 목록과 상세 화면에서 일치하고, 다른 활동의 자료와 섞이지 않는다.

### F-02. 위임 수준 및 알림 설정

**목적:** 사용자가 AI의 관여 수준과 알림 방식을 설정한다.

| 위임 수준 | 서비스에서의 의미 |
|---|---|
| 제안만 받기 | 다음 행동을 제안함 |
| 결과까지 준비하기 | 자료·초안·변경안을 준비함 |
| 확인 후 실행하기 | 준비한 내용을 보여주고 사용자 확인 후 실행함 |

- 업무 예시는 제공하되, 방대한 업무 목록을 모두 선택하도록 요구하지 않는다.
- 업무별로 다르게 설정하는 방향은 유지하되 상세 동작은 미정이다.
- 알림 유형은 ‘집중 우선·균형 있게·놓치지 않기’로 구성한다.
- 유형과 상황별 토글을 같은 화면에 배치하고, 유형을 선택하면 토글이 즉시 바뀐다.
- 유형별 토글 조합과 직접 변경했을 때의 유형 표시 규칙은 미정이다.
- 설정 이후 변경할 수 있는 방향을 유지한다. 변경 화면의 세부 구조는 미정이다.

**확인 기준:** 선택 상태가 시각적으로 드러나고 저장된다. 실제 후속 동작에 적용되는 범위는 3.3을 따른다.

### F-03. 오늘의 브리핑

**목적:** 하루의 예정된 활동을 파악하고 순서를 조정한다.

- 오늘 활동의 일정 시각, 할 일, 역할 또는 소속 활동을 간략하게 보여준다.
- 사용자가 활동의 표시 순서를 바꾸고 저장할 수 있다.
- 바꾼 순서는 스케줄 화면에도 반영한다. 표시 순서 변경만으로 일정 시각을 바꾸지 않는다.
- 저장된 활동 기억이 있는 경우 해당 활동의 브리핑에 반영한다.
- 서비스 미리보기에서 조작한 상태는 셋업에 이어받지 않는다.

**확인 기준:** 순서를 바꿔도 일정 시각은 유지되며, 다른 화면에서도 저장된 순서를 확인할 수 있다.

### F-04. 현재 활동 중심의 홈

**목적:** 지금 확인하고 시작할 활동을 빠르게 파악한다.

- 대표 활동 카드를 화면 중심에 배치한다.
- 카드에는 역할·활동명·지금 할 일·시각 또는 남은 시간·제공될 정보와 기능의 개요를 보여준다.
- 카드를 선택하면 해당 활동 화면에 진입한다.
- 브리핑에서 맨 위에 올린 활동을 홈에서도 먼저 보여준다.
- 상단 세포·선은 대표 활동의 진행과 마무리 시점을 표현한다. 전체 일정 흐름과 단일 활동 진행도를 혼용하지 않는다.
- 사용자가 해야 할 일과 AI가 준비한 결과·진행 중인 작업을 구분한다.
- AI 작업은 대기·실행 중·완료 상태를 표시한다.
- 홈의 펼쳐진 ‘오늘의 스케줄을 확인해 보세요’ 안내를 선택하면 스케줄 화면으로 이동한다.

**확인 기준:** 사용자 일정의 진행 상태와 AI 작업 상태가 서로 다른 정보로 인지되며, 카드에서 예상한 활동 화면으로 진입한다.

### F-05. 다이나믹 UI

**목적:** 활동의 수행 목적과 현재 상황에 맞는 화면을 제공한다.

다이나믹 UI는 역할별 색상이나 제목만 바꾸는 기능이 아니다. 같은 서비스 안에서도 활동에 필요한 자료, 조작 도구, 정보의 우선순위와 배치를 달리해 사용자가 필요한 일을 이어가게 한다.

| 활동·상황 | 주요 정보 | 주요 기능 |
|---|---|---|
| 리서치 검토 | 기존 문서, 추가 조사 작업 상태 | 자료 열람, 목록 복귀 |
| 촬영 준비 | 촬영 레퍼런스, 메모, 날씨 영향 | 자료 확인, 조건 전달, 대안 검토 |
| 일정 조정 | 기존·변경 일정과 제안 근거 | 변경 수락, 보류 또는 닫기 |
| 러닝 문의 대응 | 공통 문의, AI 판단, 코스 후보 | 후보 비교, 코스 선택, 공지 확인·발송 |
| 러닝 측정 | 경과 시간, 거리, 페이스, 심박수 | 측정 시작·일시 정지, AI 업무 요청 |

- 첫 UT에서는 미리 설계한 화면과 컴포넌트를 활동·상태에 따라 표시한다.
- 활동 전환 후에도 해당 활동의 자료, 기억, 진행 상황은 유지한다.
- 새로운 상황이 생기면 그 활동 안에서 필요한 정보와 선택지를 제공한다.
- UI 변화 자체가 일정 완료, 제안 수락, 외부 실행을 의미하지 않는다.

**확인 기준:** 활동별 정보와 기능이 실제로 달라지고, 활동을 다시 열었을 때 저장된 맥락을 확인할 수 있다.

### F-06. 역할·활동 전환

**목적:** 다음 활동으로 넘어가는 이유와 변화를 알리고 전환의 주도권을 유지한다.

- 다음 활동을 시작할 시점에 전환 패널을 제공한다. 첫 UT에서는 진행자가 정해진 시점에 전환 이벤트를 적용한다.
- 패널에서 현재·다음 역할과 활동의 관계를 보여준다.
- 사용자는 현재 활동을 유지하거나 다음 활동으로 전환할 수 있다.
- 전환을 선택하면 역할 표시와 활동 화면을 함께 바꾸고, 다음 활동에 필요한 UI를 제공한다.
- ‘유지하기’를 선택하면 현재 역할을 유지한다. 이후 다른 역할의 활동을 직접 열면 해당 역할로 전환한다.
- 전환 패널이 나타났다는 이유만으로 역할을 먼저 변경하지 않는다.

**확인 기준:** 유지 선택 시 역할이 유지되고, 전환 선택 시 다음 활동의 정보·기능·역할 표시가 일치한다.

### F-07. AI 개입 및 활동 기억

**목적:** 사용자의 판단이 필요한 변화와 AI 제안을 알아볼 수 있게 전달한다.

- 전체 기획의 개입 상황은 승인 요청·일정 변동·마감 위험·협업 요청·AI 작업 완료다.
- 첫 UT에서는 일정·날씨 변화, 협업 문의, 작업 완료를 중심으로 구현한다.
- 활동 화면에서는 AI 아이콘의 움직임으로 신호를 보내고, 선택 시 상황과 제안을 보여준다.
- 홈에서는 화면 목적에 맞는 문구·캡슐·작업 상태로 표시한다.
- 알림을 열면 읽음 상태로 변경한다.
- 사용자가 전달한 조건은 해당 활동의 기억으로 저장하고, 이후 같은 활동의 브리핑과 제안에 반영한다. 표현이 달라도 같은 의미이면 같은 조건으로 처리한다.
- 활동 기억은 확인·수정할 수 있고 마지막 수정 시각을 표시한다.
- 특정 활동의 조건을 다른 활동의 제안에 섞지 않는다.
- 활동 기억 수정만으로 이미 수락한 일정을 자동 변경하지 않는다.

**확인 기준:** 개입 이유와 선택지를 확인할 수 있고, 저장한 조건은 연결된 활동에서만 사용된다. 음성 입력 포함 여부는 미정이다.

### F-08. AI 대화와 일정 조정

**목적:** 사용자의 조건과 기존 일정을 고려한 대안을 검토한다.

- 대화에서 사용자의 조건을 확인하고 일정·마감·상황을 고려한 조정안을 제시한다.
- 기존 일정과 겹치는 시간을 확정적으로 ‘가능한 시간’이라고 안내하지 않는다.
- 변경 전후 일정과 제안 근거를 함께 보여준다.
- 수락한 경우에만 일정 시각을 변경하고 완료 상태를 안내한다.
- 보류하거나 닫으면 기존 일정 시각을 유지한다. 제안의 보류·닫기 상태 구분과 재진입 동작은 미정이다.
- 첫 UT에서는 준비된 조건·데이터에 따른 대안을 제공한다. 실제 패턴 분석 기능은 구현 범위로 확정하지 않는다.

**확인 기준:** 수락 전 일정은 유지되고, 수락 후에는 관련 화면에 동일한 변경 결과가 표시된다.

### F-09. 협업 문의 대응

**목적:** 여러 사람의 공통 요청을 파악하고 대응한다.

- 공통 문의를 요약해 보여준다.
- 사람들이 보낸 문의와 AI의 판단을 출처가 다른 정보로 구분한다.
- 대체 코스 두 후보의 경로·거리·예상 시간을 비교할 수 있게 한다.
- 선택한 코스를 저장하고 공지 초안에 반영한다.
- 공지 초안을 확인한 뒤 발송 버튼을 눌러 모의 발송한다.
- 발송 전 초안과 발송 완료 상태를 구분한다.

**확인 기준:** 선택한 후보와 공지 내용이 일치하며, 발송 전에는 완료로 표시하지 않는다.

### F-10. 러닝 측정 및 백그라운드 AI 작업

**목적:** 현재 활동을 유지하면서 다른 활동의 업무를 맡기고 결과를 확인한다.

- 러닝 측정 전·측정 중·일시 정지 상태를 구분한다.
- 측정 시작 시 경과 시간과 기록이 변하고, 일시 정지 시 숫자 변화가 멈춘다.
- 페이스·심박수는 시간처럼 단순 누적 증가시키지 않는다. 첫 UT의 기록은 모의 값이다.
- 러닝 중 촬영 레퍼런스 검색 등을 요청할 수 있다.
- 요청한 AI 작업은 대상 활동에 연결하되 현재 역할은 유지한다.
- AI 작업은 대기·실행 중·완료로 관리하며 완료 전에는 결과 자료를 공개하지 않는다.
- 첫 UT에서는 진행자가 러닝 종료 이벤트를 적용해 측정 정지와 일정 완료, 요청한 작업의 완료를 진행한다.
- 결과는 기존 자료와 구분하여 보여준다. 결과 확인만으로 역할을 자동 전환하지 않는다.
- 결과 미리보기와 다른 활동 진입의 화면상 경계는 미정이다.

**확인 기준:** 작업 대상 활동과 현재 역할이 구분되며, 완료 결과가 올바른 활동에 연결된다.

### F-11. 스케줄과 리포트

**목적:** 전체 일정과 활동 결과를 확인한다.

- 스케줄은 오늘·내일의 시각, 활동, 역할, 대기·진행 중·완료 상태를 보여준다.
- 브리핑에서 바꾼 순서를 반영하고, 시간순이 아닌 경우 사용자 지정 순서임을 알린다.
- 수락한 일정 변경은 스케줄에 반영한다.
- 오늘 리포트에서는 활동별 소요 시간, 오래 걸린 활동, 반복 패턴과 피드백을 제공한다.
- 리포트 활동은 세션의 일정과 연결하며, 소요 시간과 과거 패턴에는 가상 데이터를 사용한다.
- 도움이 된 항목을 선택하고 피드백을 입력·저장할 수 있게 한다.
- AI 내부 처리 과정을 모두 나열하기보다 개입 결과와 사용자에게 의미 있는 변화를 보여준다.
- 피드백에 따른 실제 AI 고도화는 첫 UT 검증 범위에 포함하지 않는다.
- 주간 리포트는 주간 패턴, 시즌 리포트는 활동 기간별 반복 패턴과 다음 기간의 피드백을 다룬다. 상세 구현은 첫 UT에서 제외한다.

**확인 기준:** 일정 변경·진행 상태와 리포트의 활동 연결이 일치하고, 피드백 저장 여부를 확인할 수 있다.

## 6. 데이터 및 상태 원칙

### 6.1 공통 관리 항목

| 대상 | 관리해야 할 정보 |
|---|---|
| 역할·활동 | 식별자, 표시 이름, 역할과 활동의 연결, 설명·목표 |
| 일정 | 활동 연결, 예정 시각, 진행 상태 |
| 브리핑 | 사용자 지정 표시 순서 |
| 자료 | 연결 활동, 기존 자료 또는 AI 작업 결과 여부 |
| 활동 기억 | 연결 활동, 조건, 마지막 수정 시각 |
| AI 작업 | 대상 활동, 요청 내용, 실행 상태, 완료 결과 |
| 알림 | 관련 상황, 읽음 여부 |

이는 개념적 데이터 요구사항이며 DB 스키마나 API 명세를 확정한 표가 아니다. 피드백에서 선택한 항목의 별도 식별값 저장 여부는 추가 확정이 필요하다.

### 6.2 상태 변경 규칙

| 사건 | 변경할 상태 | 함께 변경하지 않을 상태 |
|---|---|---|
| 브리핑 순서 변경 | 표시 순서 | 일정 시각 |
| 일정 제안 수락 | 대상 일정 시각, 제안 상태 | 다른 활동의 기억 |
| 전환 제안 유지 | 현재 역할 유지 | 다음 역할로의 전환 |
| 다른 역할 활동 진입 | 현재 역할·열린 활동 | 자료·활동 기억의 삭제 |
| 알림 열기 | 읽음 여부 | 제안 수락·공지 발송 여부 |
| AI 작업 완료 | 작업 상태·결과 공개 | 현재 역할의 자동 전환 |
| 공지 발송 선택 | 모의 발송 상태 | 실제 외부 메시지 전송 |
| 활동 기억 수정 | 해당 활동 조건·수정 시각 | 이미 수락한 일정 |

일정 상태와 AI 작업 상태는 별도로 관리한다. 화면을 열거나 전환했다는 이유만으로 일정을 완료 처리하지 않는다. 팀 프로젝트 일정은 Task 5 직전에 진행자가 완료하고, 러닝 일정은 Task 10-1에서 진행자가 종료를 적용하면 완료된다. 추가 조사 작업은 일정 완료와 자동으로 연동하지 않는다. 베이스라인에 없는 일정 시작 조건은 미정이다.

## 7. UI 및 인터랙션 요구사항

- 현재 활동을 중심으로 정보 위계를 구성하고, 보조 정보와 AI 작업은 구분한다.
- 역할 태그·활동명·일정 상태·AI 작업 상태를 혼용하지 않는다.
- 네모 형태의 세포와 선을 핵심 시각 언어로 사용한다.
- 역할·활동 전환 패널은 화면 위에서 내려와 작은 반동으로 자리를 잡고, 세포가 선을 따라 이동하며 전환을 안내한다.
- 전환을 선택한 뒤 패널 아래 레이어에서 블루·바이올렛 계열 쉬머가 진행되며 다음 활동 UI를 보여준다. 패널이 올라간 후 쉬머가 약 1.5회 더 진행되는 흐름을 유지한다. 정확한 시간값은 별도 확정한다.
- AI 알림 캡슐은 텍스트 노출과 프레임 확장이 함께 진행된다. 전개 완료 후에는 펼친 상태를 유지한다.
- AI 모션은 독립적인 컴포넌트로 구성하여 배경 화면의 스크롤을 막지 않는다.
- 고정하도록 설계된 상태 바·헤더·하단 내비게이션은 스크롤 중 위치를 유지한다.
- 색상·타이포그래피·간격은 프로젝트의 UI 가이드와 디자인 토큰을 사용한다. 문서에 없는 값을 새 확정값으로 취급하지 않는다.

## 8. 구현 및 UT 운영 기준

### 8.1 구현 기준

- 첫 프로토타입은 휴대폰 화면에서 핵심 경험을 검증하는 용도로 구성한다.
- UI와 데이터 상태를 연결해 같은 일정·자료·작업이 여러 화면에서 일관되게 표시되도록 한다.
- 준비된 데이터와 응답으로 작동하는 부분을 실제 연동·AI 분석 기능과 구분한다.
- 구체적인 UT 인물·시각·대화·모의 수치는 베이스라인의 가상 제안값을 따른다. 가상 날짜는 11월 14일, 한국 시간이다.
- 화면은 React, 코드는 TypeScript, 스타일은 CSS이며 Vite로 실행한다. 첫 UT는 데이터베이스 서버 없이 브라우저에서 가상 데이터를 불러오고, 참가자 변경은 해당 세션에 저장한다. 가상 초기 데이터 `src/fixtures/croxer-ut-baseline.v1.json`과 세션 데이터는 구분한다. 서버와 외부 AI API는 팀이 그 검증을 하기로 한 경우에만 추가한다.

### 8.2 테스트 운영

- 역할 전환(Task 5·8)과 러닝 종료(Task 10-1)는 실제 시간 경과로 발생시키지 않고, 진행자가 과제 구간에서 같은 조건으로 적용한다. 비 예보 알림은 자료를 연 뒤 파일럿에서 정한 시점에 참가자마다 같게 표시한다.
- 선행 과제가 막히면 진행자가 다음 과제의 시작 상태로 옮기고 그 개입을 기록한다. 일정 교체를 끝내지 못한 경우에는 교체 완료 상태로 옮긴다.
- 참가자 교체 시 초기 데이터를 새로 복사하고, 등록·알림·변경안·작업·모의 공지·피드백을 포함한 세션 상태를 초기화한다.
- 저장은 브라우저에서 한다. 참가자별 기록은 UT 전용 키 하나로 관리할 수 있다.
- 진행자의 개입은 기록하며, 참가자 개인정보와 실제 세션 기록을 공개 저장소에 포함하지 않는다.

## 9. 검증 관점 및 구현 확인 항목

### 9.1 UT에서 확인할 질문

- 사용자가 역할과 활동의 관계를 이해하고 등록할 수 있는가?
- 홈에서 먼저 할 활동과 AI가 진행 중인 작업을 구분하는가?
- 활동별로 제공되는 정보와 기능을 이해하고 사용할 수 있는가?
- 활동 전환 후 역할·활동·자료의 관계를 파악하는가?
- AI 개입의 이유와 제안 내용을 이해하고 다음 행동을 선택하는가?
- 사용자의 조건이 해당 활동에 기억되고 이후 제안에 반영된다고 인식하는가?
- 위임한 업무의 진행·완료와 결과 위치를 이해하는가?

성공률, 수행 시간, 개입 횟수 등의 측정 기준과 통과 수치는 아직 확정하지 않았다.

### 9.2 구현 확인 목록

- [ ] 활동별 정보·기능이 구분되고 관련 자료가 올바른 활동에 연결된다.
- [ ] 브리핑 순서 변경과 일정 시각 변경이 구분된다.
- [ ] 제안을 수락하기 전에는 일정이 바뀌지 않는다.
- [ ] 전환 유지 선택과 실제 역할 전환이 구분된다.
- [ ] 활동 기억이 다른 활동에 섞이지 않는다.
- [ ] AI 작업 완료 전에는 결과가 공개되지 않는다.
- [ ] 선택한 코스가 공지 초안에 반영된다.
- [ ] 모의 발송과 초안 상태가 구분된다.
- [ ] 러닝 일시 정지 시 기록 변화가 멈춘다.
- [ ] 모션 중에도 필요한 스크롤과 화면 조작이 가능하다.
- [ ] 참가자별 초기화 후 이전 참가자의 상태가 남지 않는다.

## 10. 정책 및 별도 명세

회원가입·로그인, 연령 제한, 결제·요금, 데이터 보관·삭제, 외부 연동 권한, 운영·보안 정책은 현재 논의만으로 확정할 수 없어 요구사항을 작성하지 않았다.

네트워크 오류, 권한 거부, AI 응답 실패 등의 실제 서비스 예외 처리와 성능·접근성의 정량 기준도 미정이다. 첫 UT에서 허용하는 입력·분기와 취소·재진입 동작은 구현 전에 별도로 정해야 한다.

## 11. 미정 사항

아래 항목은 확정 요구사항이 아니다. 이전 검토에서 제안한 방향도 팀의 결정 없이 구현 기준으로 적용하지 않는다.

| 구분 | 결정할 내용 |
|---|---|
| 홈·일정 | 베이스라인에 없는 일정 시작 조건, Task 11의 오늘 대기 일정 표시 |
| 자료·역할 | 다른 활동의 결과 미리보기와 해당 활동 진입의 경계 |
| 입력 | 준비 데이터 매칭, 같은 의미로 볼 표현의 경계, 필수 입력값 |
| 설정 | 유형별 토글 조합, 수동 변경 규칙, 업무별 위임 설정 상세 |
| 안내 | UT에서 설정이 후속 동작에 반영되지 않는다는 사실의 안내 방식 |
| 음성 | 음성 입력의 포함 여부와 구현 범위 |
| 제안·취소 | 보류·닫기 상태, 취소 시 저장값, 재진입·중복 실행 처리 |
| UT 운영 | 비 예보 알림을 띄울 초 |
| 저장 | 새로고침 후 유지 범위, 피드백 선택 항목의 별도 식별 |
| 자료·디자인 | 화면과 Figma 프레임의 대응, 모션 시간 |
| 평가 | 과제별 성공 기준과 기록 방법 |
